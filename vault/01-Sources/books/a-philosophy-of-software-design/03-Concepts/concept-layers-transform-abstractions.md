# Шари мають перетворювати абстракції

## Визначення

**Корисний шар надає клієнту іншу модель роботи й бере на себе складність переходу до нижчого рівня.** Проста передача тих самих викликів без нової поведінки додає інтерфейс, але не поглиблює систему.

^aphsd-layers-definition

## Чому це важливо

Методи-посередники збільшують кількість API, які треба знати та синхронно змінювати. Їхня поява часто означає, що відповідальність за одну можливість нечітко розділена між класами.

## Приклади з розділу

- Файловий API працює з діапазонами байтів, а кеш нижче — з блоками фіксованого розміру.
- Надійний потік TCP приховує втрати й перестановки пакетів нижнього рівня.
- Текстовий API вставляє та видаляє діапазони, приховуючи розділення і з’єднання рядків внутрішнього сховища.

## Ознаки в коді

- Клас майже повністю повторює API іншого класу й пересилає аргументи.
- Зміна нижчої сигнатури вимагає такої самої зміни в обгортці.
- Клієнти змушені самі узгоджувати деталі внутрішнього подання.

Можливі виправлення: відкрити нижчий клас клієнтам, перерозподілити відповідальність або об’єднати нероздільні класи. Вибір залежить від того, яку роботу має приховувати кожна межа.

## Межі правила

Однакова сигнатура не доводить зайвість методу. Диспетчер додає вибір виконавця; альтернативні драйвери додають різні реалізації спільного контракту. Декоратор теж може виконувати корисну роботу, але її варто порівняти з ціною обгортання API. Red flag — привід дослідити дизайн, а не автоматична заборона.
