# Спільні налаштування без передачі через кожен метод

## Проблема

Уявімо програму, яка формує звіт і надсилає його на сервер. Адреса сервера потрібна лише відправнику, але її передають через увесь ланцюжок:

```text
сформуватиЗвіт(адреса)
  → підготуватиВідправлення(звіт, адреса)
    → надіслати(звіт, адреса)
```

Перші дві функції не використовують адресу — лише переносять її далі. Якщо додати ще й час очікування відповіді, доведеться дописати параметр у кожній із них.

## Рішення: передати налаштування під час створення об’єкта

**Збери спільні налаштування в об’єкт і передай його тому, хто їх використовує.** Цей об’єкт налаштувань називають **контекстом**. Відправник зберігає його, тому під час кожного надсилання достатньо передати лише звіт.

^aphsd-context-definition

Спрощений приклад TypeScript. Замість справжнього мережевого запиту він виводить дію в консоль:

```typescript
type Context = {
  readonly serverUrl: string;
};

class ReportSender {
  constructor(private readonly context: Context) {}

  send(report: string): void {
    console.log(`Надсилаємо «${report}» на ${this.context.serverUrl}`);
  }
}

// Налаштовуємо відправник один раз.
const sender = new ReportSender({ serverUrl: "https://example.com" });

// Далі передаємо лише дані, які змінюються.
sender.send("Звіт за понеділок");
sender.send("Звіт за вівторок");
```

Тепер код, який готує звіт, працює з готовим `sender` і не переносить адресу сервера через кожен виклик. Якщо ж передавати `context` через усі ті самі функції, проблема залишиться — зміниться лише назва параметра.

## Що важливо пам’ятати

- **Це не глобальна змінна.** Можна створити два відправники з різними налаштуваннями, наприклад для тестового та робочого серверів.
- **Контекст не потрібен для кожного аргументу.** Сам звіт правильно передавати в `send`, бо він змінюється від виклику до виклику.
- **Не складай у контекст усе підряд.** Якщо відправнику потрібна лише адреса, можна передати в конструктор просто адресу. Об’єкт зручний для кількох пов’язаних налаштувань.
