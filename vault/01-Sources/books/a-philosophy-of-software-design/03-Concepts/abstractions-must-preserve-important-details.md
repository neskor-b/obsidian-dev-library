# Абстракції мають зберігати важливі деталі

## Визначення

**Абстракція — це спрощений спосіб працювати з чимось складним.** Вона прибирає зайві подробиці, але залишає правила, які потрібно знати для правильного використання.

^aphsd-abstraction-important-details-definition

## Простий приклад

Уявімо метод `save(document)`. Коду, який його викликає, зазвичай не потрібно знати, як дані розкладено по блоках на диску.

Але може бути важливо знати, що означає завершення `save()`: дані лише передані в буфер для подальшого запису чи вже збережені так, що переживуть збій живлення в межах обіцяних гарантій?

Якщо програма обіцяє користувачеві надійне збереження, ця різниця впливає на її правильність. Метод має чітко описувати свої гарантії, а за потреби бібліотека має надавати окрему операцію для надійного запису.

Це навчальне пояснення прикладу зі збереженням даних. Конкретні гарантії залежать від API та системи.

## Чому це важливо

Коротка назва методу ще не робить його зрозумілим. Людина має знати, який результат вона отримає, які помилки можливі та яких правил треба дотримуватися.

Ці обіцянки й вимоги називають **контрактом**. Наприклад: «метод повертає користувача за ID, а якщо його немає — повертає `null`». З контракту має бути зрозуміло, як правильно написати код навколо виклику.

## Ознаки в коді

- Опис методу пояснює результат, можливі помилки й важливі обмеження.
- Зрозуміло, чи метод змінює переданий об’єкт або інший стан програми.
- Якщо операції потрібно викликати в певному порядку, це явно зазначено.
- Для звичайного правильного використання не потрібно читати внутрішній код методу.

> [!warning] Оманлива простота
> Якщо метод виглядає простим, але для його використання треба здогадатися про приховані умови, абстракція приховала забагато. Ці умови потрібно пояснити або прибрати потребу в них.

## Уточнення з розділу 5

Те саме стосується налаштувань. Якщо бібліотека не знає, скільки користувач готовий чекати на результат, їй може знадобитися доступний параметр тайм-ауту. Внутрішні кроки виконання можна приховати, а потрібний користувачеві вибір слід залишити.

> [!tip] Як перевірити
> Чи можна правильно використати метод, прочитавши лише його опис? Якої інформації бракує для цього?

Той самий принцип пояснює, чому [[01-Sources/books/a-philosophy-of-software-design/02-Chapters/ch-06-general-purpose-modules-are-deeper#^aphsd-ch06-false-abstraction|`backspace(cursor)` у розділі 6]] є хибною абстракцією: вона приховує рішення, яке насправді потрібне його викликачу.
